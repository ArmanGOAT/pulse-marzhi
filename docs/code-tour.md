# Путеводитель по коду «Пульса маржи»

Как пользоваться: читайте модули в порядке движения данных (раздел 1). У каждой функции указана строка: в VS Code `Cmd+клик` по ссылке открывает файл на нужном месте. Раздел 3 — команды, чтобы пощупать код руками. Раздел 4 — частые технические вопросы с ответами.

## 0. Карта проекта

```
config/                 все цифры и настройки (YAML): допущения с источником, «ручки», радар, правила регулятора
data/raw/               25 снимков реестра mpa.uz (SHA-256 в manifest.json) и курсы ЦБ — лежат в git
src/pulse/
  config.py             YAML → pydantic-модели (проверка типов при загрузке)
  data/                 снимки реестра → панель «упаковка × месяц» → события пересмотра
  ml/                   радар: признаки, модели, эксперименты
  domain/               экономика одной упаковки, склад, формула потолка цены
  decision/             сценарии Монте-Карло и оптимизатор
  products.py           поиск препарата, карточка, проверка списка
  api/main.py           FastAPI: все эндпоинты + раздача фронта из web/
  export/report.py      PDF и Excel
web/                    фронт без фреймворков: index.html (демо), check.html (проверка), js/, css/
tests/                  70 тестов, файл на модуль
artifacts/experiments/  запуски радара: конфиг, метрики, модель, прогнозы
```

## 2. Модули

### Настройки — [config.py](../src/pulse/config.py)
- `Param` ([:22](../src/pulse/config.py#L22)) — каждое допущение хранит значение, источник и статус (факт или оценка). В коде число берётся так: `a.v("market.annual_volume")`.
- `Levers` ([:92](../src/pulse/config.py#L92)) — «ручки» оптимизатора из `levers.yaml`: варианты закупки, транспорта, локализации.
- **Главное:** в коде нет «магических чисел», каждая цифра в YAML с источником; PDF и Excel показывают этот список на листе «Допущения».

### Данные — [data/](../src/pulse/data)
- `mpa_api.download` ([:70](../src/pulse/data/loaders/mpa_api.py#L70)) — скачивает ежемесячный снимок госреестра цен mpa.uz.
- `registry.build_panel` ([:153](../src/pulse/data/registry.py#L153)) — склеивает 25 снимков в одну таблицу «упаковка × дата». Парсеры `parse_form`, `parse_strength`, `parse_country` ([:46–86](../src/pulse/data/registry.py#L46)) достают форму, дозу и страну из текста. Цены переводятся в USD по курсу ЦБ на дату снимка (`_rate_on`, [:101](../src/pulse/data/registry.py#L101)).
- `registry.events` ([:196](../src/pulse/data/registry.py#L196)) — находит пересмотры: базовую цену снизили на 10% и больше.
- `registry.panel` ([:124](../src/pulse/data/registry.py#L124)) — кэш с отпечатком данных (`_fingerprint`, [:109](../src/pulse/data/registry.py#L109)): пересобирается, только если снимки поменялись.
- `contracts.validate` ([:115](../src/pulse/data/contracts.py#L115)) — проверка схемы (типы, диапазоны, пропуски); при нарушении `DataQualityError`, плохие данные дальше не идут.

### Радар (ML) — [ml/](../src/pulse/ml)
**Задача:** для каждого рецептурного препарата предсказать вероятность, что в ближайшую волну его цену снизят на 10% и больше.

- **Признаки** — `build_features` ([features.py:49](../src/pulse/ml/features.py#L49)). Список в начале файла ([:16–31](../src/pulse/ml/features.py#L16)): цена за единицу; во сколько раз дороже медианы и минимума аналогов той же дозы; ранг цены; число брендов; возраст регистрации; месяцев с последнего изменения цены; снижали ли раньше; местный или импорт; страна; форма.
- **Защита от подглядывания в будущее:** признаки на дату `asof` строятся только из снимков с датой ≤ `asof` ([features.py:52](../src/pulse/ml/features.py#L52)); метка (`build_labels`, [:106](../src/pulse/ml/features.py#L106)) смотрит строго вперёд, в окно (asof, label_end]. Это проверяют тесты `test_features_ignore_future_snapshots_and_events` и `test_labels_look_only_forward` ([tests/test_ml.py:30](../tests/test_ml.py#L30)).
- **3 волны пересмотра** ([config/radar.yaml](../config/radar.yaml)): A — дек 2025–янв 2026, B — июль 2026, C — ноябрь 2026. На A подбираем гиперпараметры, на B выбираем чемпиона, на C один раз честно тестируем.
- **Модели** ([radar.py](../src/pulse/ml/radar.py)):
  - `RuleModel` ([:66](../src/pulse/ml/radar.py#L66)) — бейзлайн «чем дороже аналогов, тем выше риск»;
  - `WoELogit` ([:86](../src/pulse/ml/radar.py#L86)) — WoE-кодирование признаков + логистическая регрессия (**чемпион**);
  - `CalibratedCatBoost` ([:114](../src/pulse/ml/radar.py#L114)) — градиентный бустинг с калибровкой.
- **Пайплайн** — `run` ([:265](../src/pulse/ml/radar.py#L265)): подбор `tune` ([:183](../src/pulse/ml/radar.py#L183)) → чемпион по AUC на B ([:314](../src/pulse/ml/radar.py#L314)) → тест на C ([:317–318](../src/pulse/ml/radar.py#L317)) → финальная модель на всех волнах ([:337](../src/pulse/ml/radar.py#L337)) → прогноз на сегодня для 12 566 препаратов.
- **Порог действия** — `decision_threshold` ([:58](../src/pulse/ml/radar.py#L58)): p* = стоимость подготовки / (средняя глубина снижения × выигрыш). Для Сербана ≈ 9%: выше этой вероятности готовиться выгодно.
- **Учёт экспериментов** — `ExperimentLog` ([experiments.py:84](../src/pulse/ml/experiments.py#L84)): каждый запуск сохраняет конфиг, хэши данных, версии библиотек, метрики, модель и прогнозы в `artifacts/experiments/<дата>_<имя>/`.

**Результаты на честном тесте (волна C):**

| Модель | AUC | Точность в топ-10% | Ценность, сум на препарат |
|---|---|---|---|
| Правило (бейзлайн) | 0,63 | 23% | 38 млн |
| CatBoost | 0,67 | 28% | 56 млн |
| **WoE + логрегрессия** | **0,68** | 26% | **63 млн** |

Базовая доля снижений — 14%. «Никогда не готовиться» даёт 0, «готовиться всегда» — 38 млн.

«Ценность» — `business_value` ([radar.py:52](../src/pulse/ml/radar.py#L52)): для каждого препарата тестовой волны, если модель сказала «готовиться», выгода = глубина снижения × 3,46 млрд − 135 млн (если цену снизили) или −135 млн (если нет); если «не готовиться» — 0. Затем среднее по всем 12 213 препаратам. Экономика (3,46 млрд и 135 млн) взята у Сербана и применена ко всем препаратам, поэтому это мера для сравнения моделей в деньгах, а не реальная выгода каждого препарата.

### Экономика — [domain/](../src/pulse/domain)
- `pack.strategy_table` ([:34](../src/pulse/domain/pack.py#L34)) — все 8 640 сочетаний «ручек».
- `pack.components` ([:125](../src/pulse/domain/pack.py#L125)) — себестоимость упаковки по статьям (закупка, доставка, таможня, склад, маркетинг, локализация) сразу для всех стратегий, векторно. `breakdown` ([:201](../src/pulse/domain/pack.py#L201)) — то же для экрана «Упаковка».
- `inventory.simulate` ([:32](../src/pulse/domain/inventory.py#L32)) — склад по дням: сколько упаковок лежит в день пересмотра при N поставках в год. `devaluation_loss` ([:71](../src/pulse/domain/inventory.py#L71)) — сколько теряем на остатках, если цену снизят.
- `regulation.reference_price` ([:115](../src/pulse/domain/regulation.py#L115)) — формула потолка цены по референтным странам (правила в `config/regulation/`).

### Оптимизатор — [decision/](../src/pulse/decision)
- `scenarios.generate` ([:63](../src/pulse/decision/scenarios.py#L63)) — 2 000 вариантов будущего: курс, спрос, стоимость логистики, будет ли пересмотр (вероятность от радара, `radar_probability`, [:51](../src/pulse/decision/scenarios.py#L51)) и на сколько (`empirical_cuts`, [:37](../src/pulse/decision/scenarios.py#L37): выборка из 2 450 реальных снижений импортных препаратов).
- `optimize` ([optimizer.py:82](../src/pulse/decision/optimizer.py#L82)), по шагам:
  - [:91–94](../src/pulse/decision/optimizer.py#L91) — вероятность от радара и генерация сценариев;
  - [:111–115](../src/pulse/decision/optimizer.py#L111) — страховой запас и сколько товара на складе в день пересмотра;
  - [:133](../src/pulse/decision/optimizer.py#L133) — цикл пачками по 720 стратегий: матрица 720 × 2 000 → сразу свёртка в риск убытка, ожидаемую прибыль, перцентили;
  - [:166](../src/pulse/decision/optimizer.py#L166) — `margin_durable`: маржа после того, как скидки уйдут в новый потолок;
  - [:171–174](../src/pulse/decision/optimizer.py#L171) — фильтр: цель, риск убытка ≤ 10%, бюджет, срок;
  - [:179](../src/pulse/decision/optimizer.py#L179) — сортировка: вложения → срок → прибыль;
  - [:183–188](../src/pulse/decision/optimizer.py#L183) — если плана нет: лучший безопасный по марже или наименее рискованный;
  - `_actions` ([:241](../src/pulse/decision/optimizer.py#L241)) — разница «план − сейчас» в виде списка мер; эффект каждой меры считается включением только её одной.

## 4. Частые технические вопросы

**Нет ли утечки данных из будущего?**
Признаки строятся только из снимков с датой ≤ asof ([features.py:52](../src/pulse/ml/features.py#L52)), метка смотрит строго вперёд. Тестовая волна C не использовалась ни при подборе, ни при выборе модели. Это проверяется тестами ([test_ml.py:30–46](../tests/test_ml.py#L30)).

**Почему логрегрессия, а не бустинг?**
На валидации (волна B) AUC 0,71 против 0,66, на тесте 0,68 против 0,67. При этом WoE-логрегрессия объяснима (видно вклад каждого признака) и устойчивее при всего трёх волнах.

**AUC 0,68 — это не мало?**
Снижения редкие (14%). В топ-10% по риску снижают у 26% — почти вдвое чаще среднего. В деньгах: 63 млн сум на препарат против 38 млн у «готовиться всегда» и 0 у «никогда».

**Откуда порог 9%?**
Из экономики, а не подбором: стоимость подготовки 135 млн сум / (средняя глубина снижения ≈ 42% × выигрыш 3,46 млрд) ≈ 0,093 ([radar.py:58](../src/pulse/ml/radar.py#L58)).

**Как оптимизатор считает 17 млн вариантов за 0,3 с?**
numpy-матрицы пачками по 720 стратегий, каждая пачка сразу сворачивается в итоги; повторные запросы берутся из кэша.

**Почему полный перебор, а не солвер (MILP)?**
8 640 дискретных вариантов перебираются за доли секунды, это точный оптимум и честное распределение риска по каждому варианту. Солвер понадобится, когда препаратов много и бюджет делится между ними.

**Откуда сценарии?**
Курс — из истории ЦБ, глубина снижения — из 2 450 реальных снижений, вероятность — от радара.

**Как воспроизвести результат?**
`seed=42`; хэши снимков в `data/raw/mpa_api/manifest.json`; каждый запуск радара сохраняет конфиг, окружение и метрики.

**Как обновлять?**
`make data-latest && make train` → коммит → CI сам прогоняет тесты и выкладывает.

**Что если mpa.uz недоступен?**
Сайт от него не зависит: данные и прогнозы лежат в образе.

**Безопасность?**
pydantic-валидация входов, лимит файла 2 МБ, CSP без внешних скриптов, лимит запросов в nginx.

**Честные ограничения (лучше сказать самим):**
- оптимизатор пока только для ривароксабана: затраты есть только для Сербана;
- в высоком уровне риска модель немного завышает: предсказано ≥ 30%, фактически 26 из 100;
- «скорее безрецептурный» — догадка: в реестре только 24 безрецептурные позиции.
