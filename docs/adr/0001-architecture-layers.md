# ADR-0001. Слоистая архитектура с одним вычислительным ядром на Python

- Статус: принято
- Дата: 2026-11-17

## Контекст
Жюри оценивает техническую сложность, бизнес и отраслевую релевантность. До защиты меньше суток. Нужны правильный расчёт, проверяемые цифры и интерфейс, который не стыдно показать.

## Решение
Семь слоёв, каждый зависит только от нижних:

1. Данные: загрузчики, схемы, хранилище с датами действия (`src/pulse/data`).
2. Предметная логика: правила ценообразования по датам, двойник упаковки, симулятор склада (`src/pulse/domain`).
3. ML: признаки на дату, радар пересмотра, прогон прошлых пересмотров (`src/pulse/ml`).
4. Решения: сценарии и оптимизатор с ограничениями (`src/pulse/decision`).
5. Сервис: API на FastAPI и выгрузка PDF/Excel (`src/pulse/api`, `src/pulse/export`).
6. Интерфейс: интерактивная страница (`web/`).
7. Эксплуатация: тесты, Docker, конфиги, реестр моделей.

Вся логика живёт в одном пакете `pulse`. Интерфейс и LLM-слой вызывают его через API и ничего не считают сами.

## Последствия
- Плюс: одна реализация расчётов, тесты покрывают всё, что видит жюри.
- Плюс: модули меняются независимо, данные подменяются с синтетики на реальные без правки логики.
- Минус: больше файлов, чем у скрипта на Streamlit. Принимаем ради проверяемости.
- Отказались: микросервисы, очереди, Kubernetes, готовый feature store. Для одного препарата и ноутбука это лишняя сложность.
